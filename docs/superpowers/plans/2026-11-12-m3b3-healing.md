# M3b-3: Healing 初版 (Stitch + Tolerance Chain) Implementation Plan

> **For the implementing agent:** follow the five-step TDD cycle for every task,
> in order. Run the RED command before writing production code, then the GREEN
> command, then commit. Do not batch tasks into one commit.

**Goal:** Add `heal_brep`, a transactional stitcher that closes small gaps
(1e-6 scale) between open boundary loops of one planar, straight-edged B-rep
shell: weld near-coincident vertices, sew paired boundary edges into shared
edges, raise the tolerance chain explicitly and monotonically, and reject gaps
it cannot close with a located, quantified diagnostic. Satisfies QA-12.

**Architecture:** `heal_brep` edits a `Brep` through `SolidEditor` (the only
mutation path), so every attempt is validated by `commit()` before it is
published. It is a "healing 初版": vertex welding, edge sewing, tolerance
re-assignment, and rejection diagnostics. Small-edge collapse, small-face
removal and surface re-fitting are explicitly deferred to M4 (architecture
§8.12, milestones table).

**Tech stack:** C++20, header-only `geom::v1`, doctest, CMake target
`geom_tests`, MSVC `/W4 /WX /utf-8`, GCC/Clang `-Wall -Wextra -Wpedantic`.

**Spec:** `docs/architecture/geometry-library-architecture.md` §8.12 (healing),
§4.6 (tolerance chain), §12.6 (QA-12: 1e-6 gap assembly is either bridged with
a self-consistent tolerance chain, or rejected with the gap location and
magnitude). `docs/quality/testing-strategy.md` (positive/boundary/failure per
public API; no weak assertions; determinism).

## Global Constraints

- Header-only: all new code lives in `include/geom/brep/…` with `inline`
  functions; one new `.cpp` is not allowed.
- `heal_brep` never mutates its input and never publishes a partially-healed
  Brep: on any rejection the returned `HealResult::brep` equals the input.
- Only boundary edges of the target solid are considered. Boundary edges of
  other solids are ignored.
- Tolerances are monotone non-decreasing, explicit, and capped: every raise is
  clamped by `HealOptions::max_tolerance` and reported through
  `HealReport::max_tolerance`. A raise that would exceed the cap rejects the
  heal. The cap bounds raises performed by the healer; it does not lower a
  pre-existing input chain above the cap (that input is legal). Global epsilon
  and "raise until it fits" are forbidden (architecture anti-pattern list).
- Input precondition: the whole Brep is structurally valid (loops are closed
  cycles, every edge has at most two coedges and opposite directions, handles
  and geometry indexes are live). Open shells of the target solid are allowed
  and are the gap state being healed. The Brep may contain other solids; they
  are not touched but must still satisfy the structural precondition. The
  healer checks this precondition before mutating; an unrelated invalid solid
  is a caller error, not a heal issue.
- Every error is a `Result` error or a `HealIssue`; no exceptions, no `assert`
  as the only check.
- Determinism: two identical inputs produce byte-identical Breps and equal
  reports; candidate order is by (edge index, edge index) and repaired pcurves
  are appended in ascending coedge index.
- Tests use `tests/unit/brep_heal_test.cpp` and
  `tests/unit/brep_heal_fixture.hpp`; register the test file in
  `tests/CMakeLists.txt` `GEOM_TEST_SOURCES`.

## Scope And Deviations To Approve

1. **Planar faces, straight edges only.** Initial healing handles `Plane3`
   faces; every edge of the target solid must have `curve == kNoGeometry` or hold
   a `LineCurve3`. Any non-planar surface or other curve type returns
   `unsupported` before editing; curved gap bridging is M4.
2. **Single solid, welded vertices + sewn edges only.** Face splitting and
   non-manifold stitching are out of scope. A healed shell must end up closed
   (each edge used exactly twice inside the shell).
3. **No small-edge collapse / face removal / NURBS re-fit.** Those are M4 per
   the milestone table; the plan documents them as deferred and keeps the
   report fields extensible.
4. **Pairing is mutual-nearest, not global optimum.** It is O(n²) over boundary
   edges; an AABB lower bound may prune a pair only when it exceeds both the
   edge's current best accepted gap and its current best rejected gap, so the
   `gap_too_large` measurement stays exact. Healing is an offline operation.
   Ambiguous ties are rejected, never guessed.
5. **Tolerance semantics:** a welded vertex takes
   `max(tol_keep, tol_drop, distance)`; edges dominate their vertices, faces
   dominate their edges and coedges, the solid dominates its faces. No value is
   ever lowered, and every raise is capped by `HealOptions::max_tolerance`
   (default `max_gap`); exceeding the cap rejects the heal (§8.12 "有上限").
6. **Pcurve repair is part of sewing.** The pcurve points are geometry-store
   data, so a welded endpoint leaves them stale. For **every edge incident to a
   welded vertex** (a vertical neighbour stretches too, not just the sewn edge),
   each coedge gets a fresh two-point pcurve `{project(v0), project(v1)}` in its
   own face's uv, the edge's curve is cleared to `kNoGeometry`, and `t0/t1` are
   reset to 0/1. A failed projection rejects the whole heal (original Brep
   returned).

## Review Focus

- Transactionality: a failed `commit()` must return the original Brep and a
  diagnosis, not a partial stitch.
- Tolerance chain: after a successful heal,
  `validate_tolerances(brep).ok()` is true and every raised value is reported.
- Pairing: direction compatibility, ambiguity rejection, and determinism.
- Pcurves: every coedge of a sewn edge carries a two-point pcurve whose points
  project to the welded vertices in that face's uv; no stale geometry remains.
- QA-12 both ways: 1e-6 gap closes to a valid closed solid; 1e-3 gap is
  rejected with a location within the gap band and the measured magnitude.

```cpp
namespace geom::v1 {

enum class HealIssueKind : std::uint8_t {
  none, gap_too_large, ambiguous_gap, inconsistent_orientation, invalid_result
};
const char* to_string(HealIssueKind kind) noexcept;

inline constexpr std::uint32_t kNoEntity = 0xFFFFFFFFu;

struct HealOptions {
  double tolerance = 1e-9;  // uv-projection resolution used when repairing pcurves
  double max_gap = 1e-6;    // largest vertex-to-vertex distance that may be welded
  double max_tolerance = 1e-6;  // cap for every raised tolerance (default = max_gap)
};

struct HealIssue {
  HealIssueKind kind = HealIssueKind::none;
  Point3d location{};
  double gap = 0.0;
  std::uint32_t entity_a = 0xFFFFFFFFu;  // first offending EdgeId index, kNoEntity if none
  std::uint32_t entity_b = 0xFFFFFFFFu;  // second offending EdgeId index, kNoEntity if none
  const char* message = "";
};

struct HealReport {
  std::uint32_t boundary_edges = 0;
  std::uint32_t welded_vertices = 0;
  std::uint32_t sewn_edges = 0;
  double max_closed_gap = 0.0;
  double max_tolerance = 0.0;
  bool changed = false;
  std::vector<HealIssue> issues;
};

struct HealResult {
  Brep brep;
  HealReport report;
};

// Structural preconditions: live solid id, finite options, loops closed,
// every edge used at most twice. Open shells are allowed (that is the input
// state of a gap). Returns invalid_topology / index_out_of_range / tolerance_violation
// for bad input; otherwise never errors for geometric reasons (rejections are
// reported in HealReport::issues with the input Brep returned unchanged).
Result<HealResult> heal_brep(const Brep& brep, SolidId solid, const HealOptions& options);

namespace detail {
// Boundary edges of `solid`: edges used exactly once by the faces of its
// shells. Sorted ascending by index. Empty when the solid is unknown or closed.
std::vector<EdgeId> heal_boundary_edges(const Brep& brep, SolidId solid);
}  // namespace detail
}  // namespace geom::v1
```

## Task 2: Editor primitives for welding, sewing and shell closure

**Files:** modify `include/geom/brep/solid_editor.hpp`;
`tests/unit/brep_heal_test.cpp`.

**Interfaces (Produces):**

```cpp
// Inside SolidEditor:
// Merge `drop` into `keep`: every edge endpoint pointing at `drop` is
// retargeted to `keep`, `keep.tol` becomes the maximum of both tolerances and
// the true distance, and `drop` is released. Fails with invalid_topology for
// dead handles or keep == drop, and with unsupported if the merge would create
// a self-loop edge (v0 == v1).
Result<void> merge_vertices(VertexId keep, VertexId drop);

// Merge the boundary edge `drop` into `keep`: every coedge using `drop` is
// retargeted to `keep` with `reversed` recomputed from the endpoint
// correspondence, and `drop` is released. `keep.tol` is left unchanged;
// raise_tolerances(cap) re-establishes dominance. Both edges must have two
// distinct live endpoints that are already welded pairwise; otherwise returns
// invalid_topology.
Result<void> merge_edges(EdgeId keep, EdgeId drop);

// Set the shell's closed flag. Throws nothing; returns invalid_topology if the
// shell is dead, not_closed if the shell would claim closed while any of its
// edges is used fewer than twice inside that shell.
Result<void> set_shell_closed(ShellId shell, bool closed);

// Replace a coedge's pcurve index (kNoGeometry clears it; any other index must
// be < pcurves.size(), else index_out_of_range).
Result<void> set_coedge_pcurve(CoedgeId coedge, std::uint32_t pcurve);

// Replace an edge's curve index and parameter interval. The curve index is
// valid when it is kNoGeometry or < curves.size(); otherwise index_out_of_range.
Result<void> set_edge_geometry(EdgeId edge, std::uint32_t curve, double t0, double t1);

// Raise the staged tolerance chain monotonically: every edge to at least the
// maximum of its two vertex tolerances, every face to at least the maximum of
// the tolerances of the edges and coedges it uses, every solid to at least the
// maximum face tolerance in its shells. Every raised value must stay at or
// below `cap`; otherwise returns tolerance_violation and changes nothing.
// Returns the largest value set (0 when nothing changed).
Result<double> raise_tolerances(double cap);
```

**Steps:**

1. Add tests: welding a duplicated vertex retargets its edges and raises its
   tolerance to the distance; `keep == drop` fails with invalid_topology;
   after welding both endpoint pairs, merging two boundary edges leaves one edge
   with two opposite coedge directions and **does not widen** `keep.tol`; `set_coedge_pcurve` and
   `set_edge_geometry` round-trip through `brep()` and reject an out-of-range
   geometry index with `index_out_of_range`; setting `closed=true` on a sheet
   with boundary edges fails with not_closed and succeeds once the sheet is
   actually closed; `raise_tolerances` rejects a cap smaller than a needed value
   and changes nothing.
2. Run: RED (methods missing).
3. Implement in `solid_editor.hpp`, reusing `staged_`, the allocators, and the
   same error strings as the existing methods.
4. GREEN, then commit `feat(m3b3): add editor primitives for stitching`.

Implementation notes:

- `merge_vertices` must scan `staged_.edges_` once; for each edge whose `v0`
  or `v1` equals `drop`, retarget and update tol. Then check the edge is not a
  self-loop, release `drop`, and bump `generation` via the allocator (the
  allocator's `release` already does this).
- `merge_edges` recomputes direction as
  `reversed_new = (traversal_start_after_weld != keep.v0)`, where
  `traversal_start_after_weld` is `coedge.reversed ? drop.v1 : drop.v0`’s
  welded survivor. It must also copy the drop edge's curve only when `keep`
  has no curve (`keep.curve == kNoGeometry`). This predicate is the same one
  the pairing direction test must use; comparing raw `reversed` flags is wrong
  when the endpoint correspondence flips v0/v1.
- `set_shell_closed(true)` counts uses per edge restricted to the shell's faces
  and fails if any count differs from two.
- `raise_tolerances(cap)` walks edges → coedges/faces → solids; a value that
  would exceed `cap` returns `tolerance_violation` with message
  `"heal_brep: tolerance cap exceeded"` before mutating anything.

## Task 3: Pairing plan and the healing pipeline

**Files:** `include/geom/brep/heal.hpp`; create
`tests/unit/brep_heal_fixture.hpp` (initially only `TornSheet`);
`tests/unit/brep_heal_test.cpp`.

**Interfaces (Produces):**

```cpp
namespace detail {
struct HealVertexWeld {
  VertexId keep{};  // lower index
  VertexId drop{};  // higher index
};

struct HealEdgePair {
  EdgeId keep{};      // lower index
  EdgeId drop{};      // higher index
  std::array<HealVertexWeld, 2> welds{};  // endpoint correspondence, keep < drop
  bool same_direction = false;  // coedge traversal directions agree
  double gap = 0.0;             // max endpoint distance under the chosen mapping
};

struct HealPlan {
  std::vector<HealEdgePair> pairs;
  std::vector<HealIssue> issues;
};

Result<HealPlan> heal_plan(const Brep& brep, std::span<const EdgeId> boundary,
                        double max_gap);
}  // namespace detail
```

Tolerance raising is `SolidEditor::raise_tolerances(max_tolerance)` (Task 2),
called after the welds and shell closure, before `commit()`.

**Algorithm:**

1. Zero-length boundary edges are invalid geometry: `heal_plan` returns
   `invalid_topology "heal_plan: boundary edge has zero length"` before
   considering pairs. For every candidate pair `(i, j)`, `i < j`, that shares no
   vertex, compute both endpoint matchings (`d00+d11`, `d01+d10`) and keep the
   lexicographically best by `(max endpoint distance, sum)`; `gap` is that
   maximum. **Every** candidate is kept here — `max_gap` filters acceptance in
   step 2, never measurement, because step 4 must report a rejected distance.
2. Best accepted candidate per edge: among candidates with `gap <= max_gap`,
   take the lexicographically best `(gap, sum)`. Two accepted candidates whose
   gaps differ by at most `1e-12` (absolute model units) make the edge
   ambiguous: emit one `ambiguous_gap` issue with `entity_a` = that edge's
   index, `location` = the edge's midpoint, `gap` = the tied gap, and **all**
   that edge's candidates are excluded from acceptance. A cycle (A's best B,
   B's best C) is not ambiguous; only mutual pairs are sewn.
3. Direction compatibility uses the same predicate as `merge_edges`:
   `traversal_start_after_weld` is the vertex `coedge.reversed ? drop.v1 : drop.v0`
   mapped through `pair.welds`, and `reversed_new =
   (traversal_start_after_weld != keep.v0)`. The two uses must end up opposite:
   `reversed_new_keep != reversed_new_drop` (equivalently one coedge must end up
   traversing `keep.v0 -> keep.v1`). If they agree, emit
   `inconsistent_orientation` and do not sew. Never compare raw `reversed`
   flags: the weld may flip v0/v1.
4. Gap rejection: an edge with no accepted candidate and no ambiguity whose
   nearest candidate is farther than `max_gap` contributes to `gap_too_large`.
   Report **one** issue: the closest such pair (smallest gap; tie by lower edge
   indices), `gap` = that distance, `location` = midpoint of the closest
   endpoint pair, `entity_a/entity_b` = the pair's edge indexes. Ambiguous edges
   produce `ambiguous_gap` instead and never a gap issue.
5. `heal_brep`:
   - Validate options (`tolerance ≥ 0`, `max_gap > 0`, `max_tolerance > 0`; all
     finite) and the input topology precondition from Global Constraints.
   - Reject if any face of the target solid is not `Plane3`, or any edge used by
     its faces has a curve that is neither `kNoGeometry` nor `LineCurve3`,
     with `unsupported "heal_brep: curved geometry is not supported yet"`.
   - `plan = heal_plan(...)`; propagate its `Result` error. If the target has
     boundary edges but `plan.pairs` and `plan.issues` are both empty (every
     candidate pair was skipped because it shares a vertex, e.g. one triangular
     sheet), reject with one `invalid_result "heal_brep: no candidate pairs"` —
     never a silent no-op. If `plan.pairs.empty()`, return the input unchanged
     with `plan.issues` (no `invalid_result` for a pure gap rejection).
   - **Cap pre-check (vertices):** `merge_vertices` has no cap argument, so
     before mutating, reject with one `invalid_result`
     `"heal_brep: tolerance cap exceeded"` if any weld's resulting tolerance
     `max(keep.tol, drop.tol, pair.gap) > options.max_tolerance`. This covers
     the case where incident edges already dominate every vertex and
     `raise_tolerances` would never raise an edge.
   - `SolidEditor editor(brep)`. Build a deduplicated weld map
     `drop -> keep` from every `pair.welds` entry. A `drop` mapped to two
     different `keep` vertices (or vice versa) is `invalid_topology
     "heal_brep: weld map is inconsistent"`; the one-to-many rule is stricter
     than strictly needed here but keeps the weld deterministic. Skip entries
     whose `drop` handle is no longer alive; count unique welds and call
     `merge_vertices` once per entry. Then call `merge_edges` once per pair.
   - Repair pcurves for **every edge incident to a welded vertex** (not only
     the sewn edges: welding moves an endpoint, so a vertical neighbour
     stretches too). Iterate coedges in ascending coedge index so repair order
     is deterministic. For each coedge: `const Face& face =
     editor.brep().face(coedge.face)`; `detail::face_uv_projection(editor.brep(),
     face, options.tolerance)`, then `detail::face_uv_project(projection, point,
     0.0, false)` for the edge's `v0` and `v1` as stored in
     `editor.brep()` (staged positions, not the input), add a two-point pcurve,
     `set_coedge_pcurve`; then `set_edge_geometry(edge, kNoGeometry, 0.0, 1.0)`.
     A failed projection or a non-line curve (checked above) rejects the heal.
     Straight edges need no curve; downstream sampling falls back to `v0 -> v1`.
   - For each shell of the solid, call `set_shell_closed(true)` when all its
     edges are used twice inside it.
   - `raise_tolerances(options.max_tolerance)`.
   - `euler_characteristic(editor.brep(), solid)` must equal the input's value.
     This is a defensive assertion, not a gate that can fire here: weld+sew
     changes V and E by the same amount and leaves F unchanged, so χ is
     invariant by construction. If it ever differs, reject as `invalid_result`
     `"heal_brep: Euler characteristic changed"`.
   - `commit()`.
   - **Precedence:** if `plan.pairs.empty()`, only the plan issues are
     reported. Otherwise, if a primitive `Result` failed or `commit()` failed,
     reject with one `invalid_result` carrying that primitive error message
     first (plus `plan.issues`). If every primitive succeeded but a shell of
     the target still has a boundary edge after sewing, reject with one
     `invalid_result` `"heal_brep: a shell is still open after stitching"`
     **and carry `plan.issues` after it** (so a mixed case keeps its
     `gap_too_large`). Rejection always returns the original Brep and never
     reports a partial stitch.
   - On success fill the counters (`welded_vertices` = unique welds,
     `sewn_edges` = pairs), `max_closed_gap`, `max_tolerance`, and
     `changed = (welded + sewn) > 0`.

**Steps:**

1. Tests: the torn sheet with a 1e-6 normal offset produces 8 boundary edges
   and 4 mutual pairs with `gap ≈ 1e-6`, no issues; a 1e-3 offset with
   `max_gap=1e-6` produces no pairs and exactly one `gap_too_large` with the

   box produces no pair and `changed=false`; a zero-length boundary edge is an

3. Implement, then GREEN.
4. Commit `feat(m3b3): plan boundary stitches and heal transactionally`.

```cpp
// Every relevant field of the staged topology, in a stable order. Used to prove
// "input unchanged" and idempotence without relying on volume (an open shell
// has no volume).
std::string heal_fingerprint(const geom::v1::Brep& brep);
```

It appends, per table in index order: alive flags, generations, and every
geometry/tolerance field (vertex `point`/`tol`; edge `v0`/`v1`/`curve`/`t0`/

`closed`/`face` list; solid `shell` list and `tol`), plus the geometry-store
inventory (`curves.size()`, `surfaces.size()`, `pcurves.size()` and every
pcurve's points), formatted with `std::to_chars`/hex floats so the comparison
is exact. The store is append-only (`solid_editor.hpp:60-64`), so a repair that
appends pcurves is visible even when all topology fields match.
