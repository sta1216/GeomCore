| 项 | 内容 |
| --- | --- |
| 版本 | 1.0 |
| 日期 | 2026-11-06 |
| 适用范围 | 全库(L0–L7);与架构文档 §12 配套 |
| 上游文档 | `docs/architecture/geometry-library-architecture.md` v2.0 |
| 执行载体 | `docs/superpowers/plans/2026-11-06-m0-m1-foundation.md` |

本文回答一个问题:**什么叫「测试用例充分覆盖」,以及如何用可执行的度量证明它。**

---

## 1. 原则

1. **覆盖是风险覆盖,不是行覆盖**。行覆盖是必要条件:未执行的代码必然未验证;但行覆盖 100% 仍可能漏掉「过滤路径从未触发」「错误分支从未进入」「跨平台符号不一致」。
2. **契约即测试**。架构文档里的每条不变量(§4.6、§12.3)必须有对应的失败用例证明它真的会失败。
3. **缺陷先有红测试**。任何 bug 修复 PR 的第一个 commit 必须是复现该 bug 的失败用例。
4. **随机必须可复现**。固定种子;失败时打印种子与最小输入;语料固化进仓库。
5. **测行为不测实现**。断言公开契约(符号、误差界、拓扑不变量),不断言内部数组顺序(除非该顺序是公开契约,如 D0 确定性)。
6. **负向测试与正向同等重要**。每个 `Errc`、每个 `Result` 失败路径、每个校验器都要有「坏输入必须被拒绝」的用例。

---

## 2. 质量门槛(CI 阻塞)

| 指标 | core / numeric / primitives / curves / surfaces | cgeom / index | brep(M2+) |
| --- | --- | --- | --- |
| 行覆盖 | ≥ 95% | ≥ 90% | ≥ 85% |
| 分支覆盖 | ≥ 90% | ≥ 85% | ≥ 80% |
| 本 PR 新增/修改代码(diff 覆盖) | 100% | 100% | 100% |
| 变异分数(mutation score) | ≥ 80% | ≥ 70% | ≥ 60% |
| 每个 `Errc` 枚举值 | ≥ 1 个触发用例 | 同左 | 同左 |
| 每条公开 API | 正例 + 边界 + 失败路径 | 同左 | 同左 |
| 谓词过滤/精确两条路径 | 两条都必须被执行(计数器证明) | — | — |

规则:
- **diff 覆盖 100%** 是硬门禁:新增分支未覆盖即阻塞合并,除非在代码处标注 `// GEOM_COVERAGE_EXEMPT: <理由>` 并经评审。
- 变异测试每周夜间跑;变异分数低于门槛时生成缺口列表,下一迭代清零。
- 覆盖率以 CI 的 Linux + GCC `gcovr` 结果为准(Windows 不做覆盖率统计,避免工具链差异)。

## 3. 测试层级

| 层级 | 内容 | 运行时间预算 | 触发 |
| --- | --- | --- | --- |
| L1 单元 | 单函数/单类型;等价类 + 边界 + 错误路径 | < 30 s 全量 | 每次提交 |
| L2 组件 | 模块内组合(如 hull + delaunay 计数一致性) | < 60 s | 每次提交 |
| L3 性质/变形/差分 | 随机性质、变换不变性、与 oracle 对比 | < 5 min(快速档)/ 1 h(夜间) | PR + 夜间 |
| L4 系统/集成 | C API、序列化往返、跨语言绑定 | < 10 min | PR |
| L5 非功能 | 性能基准、TSan、fuzz、变异 | 夜间/周 | 定时 |

PR 门禁跑 L1–L2 + L3 快速档;夜间跑全量 + fuzz 1 小时 + 性能回归;每周跑变异与跨平台符号一致性。

## 5. 测试设计方法(按优先级)

### 5.1 等价类与边界值

每个数值参数至少覆盖:`0`、`±1`、`±ε` 邻域、`±1e±150`、非有限值(应被拒绝)、以及该参数的语义边界(如参数域的端点)。

### 5.2 性质测试(property-based)

用 rapidcheck 或自研生成器,固定种子,断言不变量而非具体值:

| 性质 | 断言 |
| --- | --- |
| `orient2d` 反对称 | `s(a,b,c) == -s(a,c,b)`;循环置换不变 |
| `incircle` 与 `orient2d` 一致 | 翻转 `a,b` 时 `incircle` 符号翻转 |
| Delaunay 空圆 | 每个三角形的外接圆不含其他输入点 |
| 凸包 | 所有输入点在凸包内或边界上;包顶点严格凸 |
| BVH | 射线/最近邻结果与暴力枚举一致 |
| 布尔(后续) | `A ∪ B` 与 `B ∪ A` 面积相等;`A \ A` 为空 |
| 网格化(后续) | 输出水密;体积与 B-rep 质量属性一致 |
| 序列化 | 往返后几何与属性逐字段一致 |

### 5.3 变形测试(metamorphic)

对同一算法施加保结构变换,断言结果在容差内一致:

- 平移、旋转(2D/3D 刚体)、均匀缩放(含极端尺度);
- 输入置换(结果不变,或仅索引重排);
- 网格细分/加密(结果收敛);
- 对布尔:用不同但等价的多边形表示(多余的共线点、重复起点)。

### 5.4 差分测试(differential oracle)

| 被测算子 | Oracle | 规模 | 判据 |
| --- | --- | --- | --- |
| `orient2d` / `incircle` | 整数精确行列式(int64) | 1e6 随机 + 全退化枚举 | 符号 100% 一致 |
| 2D 布尔 | Clipper2 / CGAL | n ≤ 200 | 面积/周长差 ≤ 1e-12 相对;拓扑同构 |
| Delaunay | CGAL(仅测试) | n ≤ 200, 1e3 用例 | 三角形集合等价(允许共圆重排) |
| 网格布尔 | Manifold | 小网格 | 体积差 ≤ 1e-9;流形性一致 |
| B-rep 布尔 | OCCT | 小实体 | 体积/面积/拓扑计数一致;容差内 |

Oracle 只在 `tests/oracle/` 编译,不进入安装产物;许可与供应链审查见架构文档 R8。

### 5.5 Golden 语料

每个回归缺陷最小化后入库,格式见架构文档 §6.7;语料文件必须带 `.sha256` 与一句来源说明。语料是「不可再生资源」:任何删除都需要评审。

### 5.6 模糊测试与变异测试

见 §8、§9。

## 6. 谓词与数值专项(最高风险)

1. **整数 oracle**:坐标取小整数(可精确表示),用 int64 精确计算行列式,与谓词符号逐位比对;随机 1e6 例 + 构造的全退化枚举(共线/共圆/共面)。
2. **过滤路径覆盖**:debug 构建暴露 `NumericStats{filtered, adaptive, exact}`;测试必须证明三条路径都被执行(至少一个用例触发 `exact > 0`)。
3. **ulp 扰动**:对每个退化构型做 ±1 ulp 扰动,断言符号按预期翻转/保持。
4. **尺度**:同一构型缩放到 1e-200、1e-150、1、1e150、1e200,符号必须不变(库内部按 2 的幂归一化)。
5. **跨平台符号哈希**:对固定 1e5 输入序列计算符号哈希,在 Windows/Linux/macOS × MSVC/GCC/Clang 上必须一致(D0)。
6. **禁止**用 `long double` 作为精确回退(MSVC 上不等于更高精度);精确路径必须是展开式/精确数域。

## 7. 退化语料库

目录 `tests/corpus/`:

| 类别 | 最少用例 | 内容 |
| --- | --- | --- |
| 共线/共面 | 50 | 全部共线点集、薄片、重合边 |
| 重复/近重复 | 30 | 完全相同点、1 ulp 差、重复顶点多边形 |
| 重合/相切 | 50 | 重合面、相切圆/球、共面三角形 |
| 零测度 | 30 | 零面积环、零长边、零体积壳 |
| 定向错误 | 30 | 反向绕序、混合绕序、非流形输入 |
| 极端尺度 | 20 | 1e9:1 尺度比、1e±200 |
| 非法输入 | 30 | NaN/Inf、索引越界、错误节点向量 |

生成脚本必须与语料一并提交(可复现);每个语料是 `GEOM` 二进制或最小 JSON 描述,附最小化说明。

## 8. 不变量测试(每个模块必须有「坏输入必须失败」用例)

| 模块 | 不变量 | 负向用例 |
| --- | --- | --- |
| 多边形集 | 环闭合、洞在壳内、绕序一致 | 未闭合环、洞越界、反向绕序 |
| Delaunay | 空圆、逆时针、覆盖输入 | 共圆输入、重复点、共线 |
| 凸包 | 所有点在包内、严格凸 | 共线、重复、单点 |
| BVH | 节点盒包含子节点、叶覆盖全部图元 | 空集、单图元、退化三角形 |
| B-rep(M2+) | 欧拉-庞加莱、2-coedge、容差链、pcurve 一致 | 缺 coedge、容差倒挂、悬垂 handle |
| 网格化(M2+) | 水密、无翻转、偏差有界 | 开壳、极点、超容差 |

每个不变量校验器自身也要有负向测试:喂入故意损坏的结构,断言返回具体 `Errc` 而非崩溃。

## 9. 并发与确定性

- TSan 任务:只读索引/网格上的并发查询;断言无数据竞争。
- 线程数扫描:1/2/4/8 线程运行同一 D0 用例,输出哈希必须一致。
- 并行分区测试:构造导致负载不均的输入,验证结果与线程数无关。
- 取消测试:`CancelToken` 在检查点触发后返回 `Errc::cancelled`,且不破坏输入。

## 11. 性能测试

- 基准套件独立于单元测试(`bench/`),不进入 PR 快速档。
- 环境:固定 CI runner 类型;取 5 次运行的中位数;报告相对基线的变化。
- 门禁:金标准基准回归 > 5% 阻塞合并;新基准需先建立基线(`docs/benchmarks/`)。
- 性能测试必须带正确性断言(如命中数/面积),防止「快但错」。

## 13. 缺陷与回归流程

1. 复现:记录输入、种子、平台、构建类型。
2. 最小化:用 `tools/minimize` 缩减输入(几何最小化:删除顶点/面,保持失败)。
3. 固化:加入 `tests/corpus/...` 或单测,先红后绿。
4. 修复:修复 commit 必须让新用例转绿,且不降低覆盖。
5. 复盘:同一类缺陷出现 2 次 → 增加 fuzz target 或性质测试。

## 15. 反模式(评审直接拒绝)

- 只测 happy path,没有 `Result` 失败路径;
- 断言 `>= 0` 之类的弱断言代替精确符号;
- 用随机但不固定种子、失败无法复现;
- 用 `long double` 冒充精确;
- 为了让测试过而放宽容差,而不分析原因;
- 跳过慢测试且无夜间覆盖;
- 覆盖率靠 `// istanbul ignore` 式豁免堆出来;
- 测试依赖运行顺序或全局状态。
