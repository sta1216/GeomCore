# ADR 0020: M1b arrangement 与三角剖分的实现取舍

- 状态: 接受
- 日期: 2026-11-07
- 关联: 架构文档 §8.2、§8.3、§16.3；ADR-012（2D 布尔基于 arrangement + winding）

## 背景

M1b 需要交付多边形三角剖分、CDT、2D 布尔与 KD/BVH。架构文档给出的是目标形态：
三角剖分用「单调多边形分解 + 耳切」（§8.2），arrangement 用「扫描线（Bentley–
Ottmann）」（§8.3）。完整实现这两条需要处理大量退化事件，超出本里程碑可验证的
范围。实施计划因此选择三个更简单、可证明正确、API 不变的替代方案，并把 QA-1
的 80 ms 并集门禁作为 arrangement 选择是否成立的判据。

## 决策

### 1. 三角剖分：桥接 + 耳切，而非单调分解

对带洞多边形先用桥接把洞并入外环，再对简单 CCW 环做耳切（O(n²)，精确
`sign_orient2d` 判定，共线顶点直接丢弃）。理由：M1b 没有三角剖分性能门禁；桥接 +
耳切只有几百行、容易做穷举/性质测试，且 CDT 的约束恢复也复用同一套 `detail::TriRing`
与 `detail::ear_clip`。代价是超大面（>5 万顶点）偏慢。

### 2. arrangement 求交：x 排序活动集宽相位，而非全事件扫描线

按 x 排序线段、维护活动集，只对 x 区间重叠的段做精确谓词求交，然后把交点合并进
DCEL（典型 O((n+c) log n)，最坏 O(n²)）。理由：全事件 Bentley–Ottmann 的退化
处理（重合段、三线共点、垂直段、事件顺序）远多于本里程碑能充分验证的范围；精确
符号仍是唯一判定依据，不引入容差。代价是最坏情况二次复杂度，正是 QA-1 要检验的
风险。

### 3. 自交检测：复用求交阶段记录的原始段对

`allow_self_intersections=false` 时直接遍历 arrangement 记录的 `input_pairs()`
（求交阶段已知的原始段对），按环内相邻关系（含首尾环绕）豁免邻接对，不做二次
扫描。理由：不重复计算、不会与 arrangement 的顶点合并结果产生分歧；代价是判定
依赖 arrangement 已正确记录所有相交段对。

## 判据与升级触发

**验收判据**：QA-1 并集 ≤80 ms 且面积相对误差 ≤1e-12；QA-4 构建 ≤350 ms、
≥8 Mray/s/核。两者都是 M1b 出口门禁，不得为通过而放宽。

**2026-11-07 实测（详见 `docs/benchmarks/m1b.md`）**：QA-1 耗时 FAIL（4.8–4.9 s
vs 80 ms），但 winding 播种修复后面积相对误差为 1.783e-13，已满足 ≤1e-12；
QA-4 FAIL（构建 2.6–2.7 s，0.42–0.44 Mray/s）。QA-1 已不再是正确性问题，而是
arrangement 最坏二次复杂度的直接体现。

**升级触发**：

1. winding 播种已修复（种子面改为最小顶点处有符号面积最负的入射面），QA-1 的
   面积恒等式已通过；并集仍 >80 ms，因此触发将 arrangement 求交升级为扫描线，
   另立计划。
2. M2 面网格化在 >5 万顶点的面上出现性能压力时，把桥接 + 耳切替换为单调分解。
3. QA-4 在 CI 目标硬件上复测仍不达标时，优化 BVH 构建/遍历或重新校准预算；
   不得静默修改门禁数值。

## 后果

- 正面：三个实现都只有数百行，API 与架构目标一致，可在 M2 前用性质测试与差分
  测试充分覆盖；无新增外部依赖。
- 负面：大输入的最坏复杂度更高（O(n²)）；QA-1 并集仍比预算慢约 60 倍，说明
  x 排序活动集在大输入上不足以满足 80 ms 门禁。
- 跟进：已修复 `arrangement2.hpp` 的种子面选择（不再依据出边角度，改用最小
  顶点处有符号面积最负的入射面）；下一步把 arrangement 求交换成扫描线并重跑
  QA-1；在 CI 上补 TSan 与覆盖率门禁。
