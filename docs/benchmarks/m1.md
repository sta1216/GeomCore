## orient2d 过滤路径

`build/Release/geom_bench_predicates.exe`,每次 2,000,000 次调用、重复 5 次取
min/median/max;同一批次三条独立运行:

| 运行 | min (ns/call) | median (ns/call) | max (ns/call) |
| --- | --- | --- | --- |
| 1 | 50.19 | 50.95 | 57.96 |
| 2 | 50.44 | 51.93 | 54.26 |
| 3 | 48.76 | 52.36 | 56.59 |

预算 200 ns/call;校验和 `-485760`(独立 int64 参考实现),失配时进程退出码 2。
门槛只在 `NDEBUG` 下生效,避免 Debug 构建误报。

注意:该 CPU 为 15 W 移动处理器,不同批次(冷机/热机、插电/电池)实测 min 约
48–76 ns/call。上表与 `docs/benchmarks` 中的其它批次都低于预算,但不应把绝对值
当作跨机器基线;回归判断应看同一批次内的相对变化。

## 覆盖率

本地为 MSVC + VS generator,没有 gcov/gcovr 工具链,故本机不产出覆盖率百分比。
CI 的 `coverage` job(ubuntu-24.04,gcovr 7.0-1)执行硬门禁:

- 全局:行 ≥ 90%,分支 ≥ 85%;
- `core|numeric|primitives|curves|surfaces`:行 ≥ 95%,分支 ≥ 90%;
- 数据为空时行门禁失败(不允许 vacuous pass)。

**待回填**:CI 尚未在本次会话中实际运行,覆盖率百分比未知。门禁命令与空数据
失败行为已由 Task 14 评审验证;首次 CI 通过后在此补记实际数字,在此之前不声称
覆盖率出口达成。

## 测试与安装快照

- Debug 与 Release 均为 119 用例 / 427,724 断言,0 失败。
- `cmake --install` 产出 20 个公开头文件 + `GeomCoreConfig.cmake` /
  `GeomCoreConfigVersion.cmake` / `geomTargets.cmake`,不含 doctest。
- 另建独立 consumer 工程 `find_package(GeomCore CONFIG REQUIRED)` +
  `GeomCore::core`,Release 编译运行通过(`hull=4 tris=4`)。
